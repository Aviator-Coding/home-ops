# Retired from the `ai` namespace - 2026-08-22

Six apps left `kubernetes/apps/ai/` on this date. Their manifests are gone from
Git, so Flux pruned every Kubernetes object they owned - Deployments, Services,
HTTPRoutes, ExternalSecrets, PVCs, Dragonfly instances and VolSync
`ReplicationSource`/`ReplicationDestination` objects.

What Flux never owned is still there. Postgres databases, the SurrealDB
namespace, the 1Password items and the restic repositories in Ceph, MinIO and R2
are all outside any Flux Kustomization, so none of them were touched. That is
the whole revival path: re-add the manifests, then restore the PVC through the
VolSync `ReplicationDestination` flow described in
[`kubernetes/components/volsync/Readme.md`](../../kubernetes/components/volsync/Readme.md)
(`## Restore Operations`).

`git revert` restores manifests. It does **not** restore PVC contents - only a
restic restore does.

## What went, and what stayed

| App | Deletion | PVCs pruned | Retained out of band |
| --- | --- | --- | --- |
| `kokoro` | full | none - it had none | nothing to retain |
| `miso-gallery` | full | none - it owned none | nothing of its own |
| `perplexica` | full | `perplexica`, `perplexica-dbstore`, `perplexica-uploads` | restic repos only |
| `open-notebook` | manifests only | already pruned 2026-06-07 | SurrealDB `open_notebook` ns, 1P items, restic repos |
| `open-webui` | manifests only | `open-webui` (5Gi) | Postgres `open-webui` DB, 1P items, restic repos |
| `qdrant` | manifests only | `qdrant` (25Gi) | 1P items, restic repos |

"Manifests only" means no data-bearing resource outside Flux's ownership was
touched. It does not mean the PVC survived - Flux prunes any PVC its
Kustomization created, which is why the restic repos matter.

### Restic repositories

Each app kept three repos, one per destination, all named after the app:

```
ceph   s3:<CEPH_ENDPOINT>/<CEPH_VOLSYNC_RESTIC_REPOSITORY>/<app>
minio  s3:https://nas.<domain>:9000/<MINIO_VOLSYNC_RESTIC_REPOSITORY>/<app>
r2     s3:<R2_ENDPOINT>/<R2_VOLSYNC_RESTIC_REPOSITORY>/<app>
```

Retiring an app stops its `ReplicationSource`, and retention is applied by that
source on each run, so nothing prunes these repos once they stop running. Their
last snapshots are from the morning of 2026-08-22.

## Why each one went

### `kokoro`

Stateless TTS. No PVC, no VolSync include, nothing referencing it anywhere else
in the repo or the cluster. Full delete leaves nothing behind.

### `miso-gallery`

A gallery front-end for ComfyUI output. It owned no PVC; it mounted
`comfyui-output` read-only and was that claim's only consumer besides ComfyUI
itself, which keeps the claim and its data. ComfyUI is unaffected.

`kubernetes/apps/base/ai/comfyui/app/pvc.yaml` and `helmrelease.yaml` still
carry comments naming `miso-gallery` as a reader of that claim. They were left
as written here rather than edited, because `ai/comfyui` is in scope for a
separate, same-day sibling task (its suspension state); this note is the
record of that stale wording, not a missed cleanup.

### `perplexica`

Retiring it also removed the second-volume backup coverage that #1374 added the
same morning for `perplexica-dbstore` and `perplexica-uploads`. That coverage
lived entirely in `kubernetes/apps/ai/perplexica/ks.yaml`, so deleting the app
took it with it and no `ReplicationSource` is left backing up a deleted app. The
shared `kubernetes/components/volsync/backup` component that PR introduced is
untouched - `selfhosted/syncthing` and `selfhosted/paperless-ngx` still use it.

Note that `docs/backups/volsync-coverage-2026-08-22.md` predates this retirement
and still discusses the perplexica claims. `docs/reference.md` already marks that
report as a historical snapshot.

### `open-notebook`

Its workloads and PVC were pruned back on 2026-06-07; only the manifests and a
commented-out kustomization entry survived, as a revival stub. Nothing was
running, so this is a pure manifest cleanup. Its SurrealDB `open_notebook`
namespace on `surrealdb.database.svc.cluster.local`, its 1Password items and its
restic repos are all untouched.

The old kustomization comment claimed a "postgres open-webui DB" was being
retained for open-notebook. That was wrong: open-notebook uses SurrealDB and has
no Postgres database at all. The comment is gone with the entry.

### `open-webui`

Retired on the captain's decision. Its Postgres database was queried before
choosing a deletion shape, because provisioned capacity says nothing about
stored content:

| Table | Rows |
| --- | --- |
| `chat` | 32 |
| `chat_message` | 110 |
| `user` | 1 (admin, via Authentik) |
| `file` | 2 |
| `model` | 451 (catalog cache, not user data) |
| `knowledge`, `memory`, `note`, `folder`, `feedback`, `prompt`, `tool`, `channel` | 0 |

The 32 chats are real, human-titled conversations (BGP config analysis, TrueNAS
firmware, hydroponics) spanning 2025-09-22 to 2026-04-04. The database is 12 MB.
Last chat activity was 2026-04-04; the admin's last login was 2026-06-13.

Idle for months, but not empty - so this is a manifest-only retirement. The
`open-webui` database in the `postgres-17` cluster is fully retained, along with
its 1Password items and its restic repos. Reviving it means re-adding the
manifests and pointing them back at the same database; the chat history is
untouched.

### `qdrant`

Orphaned by open-webui's retirement, verified live rather than assumed:

- Its three collections are `open-webui_files` (1 point), `open-webui_web-search`
  (3661 points) and `litellm_cache` (0 points).
- `litellm_cache` is a leftover from before this date - LiteLLM was not
  deployed anywhere in `kubernetes/` on 2026-08-22, and the collection had
  never held a point. (LiteLLM was redeployed 2026-08-26 as an unrelated,
  in-cluster-only governance layer with no Qdrant/caching dependency - see
  `docs/ai-system/litellm/README.md` - so this collection is still orphaned,
  just from a different era than a reader might assume.)
- Cluster-wide, exactly one Secret carries qdrant credentials: `ai/open-webui`
  (`QDRANT_URI`, `QDRANT_API_KEY`). No other workload can authenticate to it.
- Its access log covers the full 9 days since the pod started on 2026-08-13 and
  contains three requests, all from the localhost probes run during this
  investigation. Zero in-cluster client requests. (Qdrant excludes `/metrics`
  from that log, so ServiceMonitor scrapes are not the reason it looks quiet -
  ordinary API paths genuinely saw no traffic.)

Every vector in it is open-webui-derived RAG cache, so it is retired the same
way: manifests out, restic repos kept, revivable alongside open-webui.

Grafana still ships a `qdrant-observatory` dashboard and links to it from the
overview panel. Both were left in place - the dashboard is harmless with no
target, and Grafana is outside this change's scope.

## Verification

- `task flux:test:all` passes on the resulting tree (217 passed, whole cluster);
  the retired Kustomizations are absent from that run and the remaining `ai`
  apps all pass. `task flux:test:ns NAMESPACE=ai` is not cited here because it
  validates nothing in `ai` - see the `flux:test:ns` note in `AGENTS.md`.
- `kustomize build kubernetes/apps/ai --load-restrictor LoadRestrictionsNone`
  builds cleanly with exactly the 8 remaining apps.
- Post-merge: `kubectl -n ai get pods` should show `kokoro`, `miso-gallery`,
  `open-webui`, `open-webui-dragonfly-{0,1}`, `perplexica` and `qdrant` gone,
  with `agentgateway`, `agentmemory`, `hermes`, `searxng`, `toolhive`, `vllm`
  and the ToolHive MCP servers unaffected.
- `searxng` stays. It loses two of its three consumers here, but `hermes` still
  uses it.
